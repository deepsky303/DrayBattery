# Поддержка устройств, протоколы аккумуляторов и USB-база

[English version](device-support.md)

## Три уровня поддержки

| Статус | Значение | Чтение заряда |
| --- | --- | --- |
| **Проверено на оборудовании с DrayBattery** | Получен реальный ответ с процентом аккумулятора | Да, при проверенном подключении |
| **Протокол реализован** | В коде есть драйвер или стандартный интерфейс Windows | Только если модель корректно отвечает |
| **Распознано по USB-базе** | Справочник знает название по VID:PID | **Нет. Распознавание не равно чтению заряда.** |

## Проверено на реальном оборудовании

| Устройство | Подключение / источник | Статус | Особенности |
| --- | --- | --- | --- |
| Logitech G903 LIGHTSPEED | Локальный G HUB | Проверено | Процент аккумулятора |
| Logitech G915 X LIGHTSPEED | Локальный G HUB | Проверено | Зарядка, сон и физический идентификатор |
| Razer Wolverine V3 Pro | Windows Mode, 1532:0A4C | Проверено | Поле HID, пересчитанное из шкалы 0–255 |
| Razer Wolverine V3 Pro | Xbox Mode, 1532:0A3F | Отдельное чтение | Автоиндикатор отключён; отдельный запрос GIP в активном окне |

Это подтверждённые ответы протоколов, а не лабораторное измерение ёмкости аккумулятора.

## Обновляемая USB-база по запросу

DrayBattery умеет вручную загружать справочник [hwdata usb.ids](https://github.com/vcrhonek/hwdata/blob/master/usb.ids). Если его нет, используются названия из Windows. После загрузки база работает **офлайн**.

Команды из каталога приложения:

    DrayBattery.exe --db-info
    DrayBattery.exe --identify
    DrayBattery.exe --update-device-db

- **--db-info:** число производителей и моделей в кэше.
- **--identify:** распознавание местных USB/HID устройств по VID:PID. **Аккумуляторы эта команда не читает.**
- **--update-device-db:** HTTPS-загрузка полного справочника, проверка и безопасная замена кэша. При ошибке старый файл сохраняется.

Есть и пункт контекстного меню **Update USB device names (online)…**. Файл располагается в %LOCALAPPDATA%\DrayBattery\usb.ids. **При обычном запуске и опросе заряда программа не обращается к серверу базы. В запросе нет VID/PID, серийных номеров или списка твоих устройств.**

[Лицензия справочника](https://github.com/vcrhonek/hwdata/blob/master/LICENSE) — GPL-2.0-or-later или XFree86 1.0. Выбранное GPL-совместимое использование соответствует GPL-3.0-or-later нашего проекта.

**Почему не скачиваются готовые драйверы аккумуляторов?** Неизвестные HID-команды могут нарушить работу периферии. Онлайн-база хранит только названия, а новые протоколы входят в обычные проверенные версии приложения.

## Идентификаторы, дубликаты и новые устройства

### Диагностика без команд периферии

    DrayBattery.exe --diagnose
    DrayBattery.exe --status
    DrayBattery.exe --dump
    DrayBattery.exe --list --windows-only
    DrayBattery.exe --list --ghub-only

`--diagnose` показывает признаки соединения Bluetooth, сохранённый заряд Windows,
стандартные ответы XInput/WGI и дескрипторы HID. `--status` читает состояние
работающего интерфейса: число видимых устройств по типам, наличие виджета и возраст
результата опроса. Эти команды не посылают HID/GIP-команд и не меняют настройки устройств.

Обычный `--list` и `--list --wolverine-only` запускают активное чтение аккумуляторов.
Они блокируются, пока работает основной экземпляр DrayBattery, чтобы два процесса
не отправляли команды одному приёмнику одновременно. Отдельный режим Wolverine
использует только GET `0x07/0x80`; неподтверждённый флаг `0x07/0x84` больше не считается
состоянием зарядки. Для локальной проверки интерфейса есть запуск `--os-only`:
только свойства Windows и локальный G HUB, без команд периферии.

Текущее исправление проверено на Wolverine `1532:0A4C` в Windows-режиме.
Если после включения USB уже появился, но заряд ещё не получен, выполняются
четыре ограниченных повтора только чтения Wolverine через 3, 8, 16 и 30 секунд
между попытками. Успешный ответ отменяет повторы. Исчезновение USB-подключения
удаляет иконку: на проверенном приёмнике Windows не различает выключение
геймпада и извлечение приёмника, поэтому последнее значение не удерживается
при отсутствующем USB-узле.
В Xbox-режиме `1532:0A3F` автоматический показ старого модельного кэша отключён;
наличие пункта отдельного GIP-считывателя не означает работающий автоиндикатор.
Этот режим требует отдельной проверки вне игры.

VID:PID означает **тип устройства**, а не уникальный физический экземпляр. Дубли объединяются только при подтверждённой аппаратной сигнатуре или связи по приёмнику/слоту. Две отдельные мыши одной модели должны оставаться разными.

Для Wolverine V3 Pro переключение режимов проверено на одном физическом контроллере; несколько одновременно подключённых пока не проверялись.

Для запроса поддержки начни с **--identify**, **--diagnose** и **--status**, укажи точную модель, прошивку и подключение, создай [обращение](https://github.com/deepsky303/DrayBattery/issues). Перед публикацией логов удали серийники, личные пути и уникальные аппаратные сигнатуры. Одного названия модели недостаточно для реализации протокола аккумулятора.
