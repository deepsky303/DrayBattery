**[ФАКТ] Причина реальной регрессии**

Обезличенная диагностика показала два присутствующих физических HID++ приёмника:
`046D:C539` и `046D:C547`. Оба устройства G HUB находились в `ACTIVE`.
На этом ПК G HUB добавляет к полному USB instance ID числовой суффикс `:<номер>`.
И G HUB, и HID++ использовали `MI_02`: несовпадение MI здесь не было причиной.
Старое точное сравнение отвергало оба пути; поиск PnP-узла с суффиксом тоже не проходил.
После удаления суффикса оставшаяся полная строка совпала с присутствующим USB-узлом
для каждого отдельного приёмника. Исходные пути, сигнатуры и контейнеры в отчёт не включены.

**[ИЗМЕНЕНО] Реализация**

- `src/drivers/logitech_transport.h`: обработка числового суффикса, затем проверка полного
  instance ID. Сопоставление через общий физический USB-предок также учитывает коллекции
  клавиатуры/мыши, которые сами не являются HID++.
- `src/drivers/ghub.cpp`: если коллекции не доказывают соответствие, точный USB-узел G HUB
  разрешается через `CM_Locate_DevNodeW(..., CM_LOCATE_DEVNODE_NORMAL)`, затем его USB-предок
  сравнивается с полным физическим идентификатором HID++ приёмника. Результат сопоставления
  используется повторно для той же записи текущего снимка G HUB.
- `tests/logitech_driver_test.cpp`: суффиксы, разные MI, два одинаковых PID, неоднозначность,
  противоречивый предок, отсутствующий приёмник и неправильный PID.
- `tests/ghub_match_test.cpp`: производственный PnP-сопоставитель с имитацией только трёх
  читающих функций Configuration Manager. Проверяется `NORMAL`, разные MI, порядок двух
  одинаковых PID, отсутствие узла, ошибка обхода и неизвестный USB-предок.
- `run-tests-msvc.cmd`: подключена девятая тестовая программа `ghub_match_test`.

Подстановки по PID и названиям модели не добавлены. При отсутствии доказанного общего
предка или неоднозначности G HUB запись не сопоставляется. Существующие 90 секунд,
отсутствие восстановления из старого кэша, физические ключи и исправления виджета сохранены.

Использованные читающие API: [CM_Locate_DevNodeW](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_locate_devnodew),
[CM_Get_Parent](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_get_parent).
`PHANTOM`, `CANCELREMOVE` и операции изменения PnP не используются.

**[РИСКИ] Границы подтверждения**

Проверка `--list` подтверждает стабильный короткий цикл при двух активных устройствах.
Она не проверяет вручную сон/пробуждение, извлечение приёмников, поведение виджета и
длительную работу. Два одинаковых PID и разные MI проверены имитацией, а не подключением
дополнительного оборудования. Неизвестный формат пути намеренно не угадывается по PID;
для него может остаться прямой HID++ путь. Настройки оборудования, аудио, автозапуска и
реестра этой правкой не изменяются.
