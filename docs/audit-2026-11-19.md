**DrayBattery: аудит жизненного цикла батареи, 19 ноября 2026**

[ФАКТ] Работа выполнена в `codex/audit-battery-lifecycle-20261119`, исходный HEAD — `b90b5f6` (v0.1.10), начальное рабочее дерево чистое. Новых коммитов нет. Проект — C++17/Win32, сборка MSVC 2022, отдельные тестовые EXE. CMS, npm, ACF и Gulp отсутствуют. Лицензия и уведомления GPL сохранены; минимальная версия Windows в сборочных флагах не менялась.

[ВЫВОД] Исправлена причина немедленного удаления спящей мыши: радио-состояние G HUB отделено от присутствия физического приёмника. Показание Logitech сохраняется приглушённым только в текущем сеансе приложения и только до `lastLiveMs + 90000`. Проверка границы — строго `< 90000`, без продления по спящим/неподключённым записям. Результат подтверждён детерминированными тестами и компиляцией, но ещё не проверен на живых G903/G915 и панели Explorer.

**Фаза 1 — восстановление отказа по исходникам**

[ФАКТ] В исходном `b90b5f6` цепочка отказа следующая:

1. `PollGHub` в `src/drivers/ghub.cpp` обнаруживает `NOT_CONNECTED`, хотя HID-интерфейс приёмника существует. Создаёт запись `connected=false`, `asleep=false`, `percent=-1`, `graceSec=0`.
2. Эта запись через `ctx.Add` захватывает весь VID/PID. Прямой `PollLogitech` и восстановление `PollLogitechCache` для него уже не выполняются.
3. `OnResults` в `src/main.cpp` пропускает `!connected`. Для прежнего значка `InvalidatedByExplicitDisconnect` возвращает `true`, период сохранения отменяется и запись удаляется.
4. `ApplyEntry` и `UpdateWidget` допускают только `connected` — никакого отдельного состояния «радиолинк недоступен, приёмник ещё на месте» у них не было.

[ВЫВОД] Регрессия следует непосредственно из ветвей обработки `NOT_CONNECTED`. Тест исходной версии также явно требовал инвалидировать такую запись. Это подтверждение поведения кода, а не аппаратное воспроизведение пользовательского сна мыши.

[ФАКТ] Обнаружены связанные проблемы:

- `OnResults` обновлял `lastSeen` при каждой записи, включая спящие записи. Пока источник продолжал возвращать кэш, значок вообще не попадал в ветвь проверки истечения срока.
- LogitechCache принимал данные до трёх суток, индексировал их только по PID и не сохранял физический идентификатор. Метка `updatedAt` записывалась с интервалом до десяти минут при одинаковом проценте, поэтому не являлась точным временем последнего живого чтения. Восстановление после перезапуска создавало спящие значки из этого кэша.
- У Logitech и G HUB был период сохранения 1800 секунд. Даже при отсутствии новых записей он не соответствовал требуемым 90 секундам.
- `MissingLogitechReceiverReport` проверял наличие ключа, а не качество показания. `NOT_CONNECTED` и кэш считались ответом, поэтому ожидание пробуждения могло оставаться на обычном интервале 60 секунд.
- Ускоренные повторы запускали весь `PollAllDevices`, включая Razer и остальные протоколы. Кроме того, этот метод отдельно повторно перечислял HID.
- `PollGHub` захватывал весь PID; `PollLogitech` выбирал первые короткую/длинную коллекции одного PID. Два одинаковых физических приёмника не были надёжно разделены.
- `MigrateLegacyLogitechCache` объединял старую запись с единственным совпадающим названием модели без доказанного аппаратного соответствия. Эта эвристика удалена.

**Фаза 2 — реализованное поведение**

| Событие | Поведение |
|---|---|
| Живой HID++ ответ батареи | Фиксируется монотонное время получения; используется возвращённое значение |
| G HUB `ACTIVE`/`CONNECTED` и успешный GET батареи | Принимается показание и время получения ответа |
| G HUB `SLEEPING` | Процент из спящего источника не принимается; используется только ранее подтверждённый процент текущего сеанса, приглушённо |
| G HUB `NOT_CONNECTED`, точный приёмник ещё присутствует | Такое же краткое приглушённое сохранение; сообщение не является новым чтением батареи |
| Ошибка GET батареи / пропавший ответ | Старое показание не обновляется; при допустимом возрасте остаётся приглушённым |
| Прошло 90 секунд от последнего живого показания | Запись удаляется даже без нового результата рабочего потока |
| Подтверждено отсутствие конкретного приёмника | Немедленное удаление без периода ожидания |
| Неполное перечисление HID / неопределённая ошибка PnP | Отсутствие не считается доказанным; разрешён только остаток тех же 90 секунд |
| Пробуждение с новым показанием | В том же применении результата восстанавливается яркий значок и новый процент; сохраняется одна запись |
| Перезапуск приложения при спящем устройстве | Значок не восстанавливается из реестрового кэша |
| Подтверждённое отключение Bluetooth | Дополнительный период Logitech-приёмника не применяется |

[ФАКТ] `src/battery_lifecycle.h` содержит общий, используемый интерфейсом и тестами алгоритм. Настраиваемая в коде константа — `draybattery::kReceiverDisplayTtlMs = 90000`. Отсчёт ведётся от момента чтения в драйвере, а не от прихода `WM_RESULTS`. Просроченный результат, задержанный другим драйвером, не получает новые 90 секунд.

[ФАКТ] Удаление по времени обслуживается отдельным UI-таймером ближайшего срока и резервной секундной проверкой. `ApplyEntry` и `UpdateWidget` дополнительно проверяют тот же срок перед показом. Повторный результат `SLEEPING`, `NOT_CONNECTED`, кэш или ошибка не меняют `lastLiveMs`. При приглушении сбрасывается старый индикатор зарядки.

[ФАКТ] Модуль `logitech_cache.cpp` теперь только проверяет корректность наблюдений. Операции чтения и записи реестрового LogitechCache полностью убраны; старые значения реестра не удалялись. Никаких показаний Logitech между запусками больше не сохраняется — неоднозначные старые записи не мигрируются.

[ФАКТ] HID-перечисление получает идентификатор экземпляра USB-предка приёмника; для Bluetooth используется контейнер/BT-экземпляр, а не USB-адаптер. G HUB сопоставляется с точным путём интерфейса или его PnP-предка. Подстановка другого приёмника по одному PID запрещена. Ключ HID++ включает экземпляр приёмника и слот.

[ФАКТ] При смене HID++/G HUB сохраняются аппаратные псевдонимы и проверенная физическая сигнатура. Разные известные сигнатуры не объединяются. `LS` и `LIGHTSPEED` нормализуются, включая лишние пробелы. Имена сами по себе не доказывают тождество. Для нескольких G HUB устройств одного приёмника порядок списка больше не выдаётся за номер HID++ слота: используются отдельные G HUB ключи. Одноустройственный путь сохраняет совместимый псевдоним слота 1.

[ФАКТ] Исправлено преобразование HID++ `BATTERY_STATUS` 0% в 100% при статусе 3. Категориальные значения HID++ помечаются приблизительными и отображаются категорией, а не как точный процент.

[ФАКТ] Локальный G HUB опрашивается отдельно с паузой 2000 мс после завершения предыдущего опроса. Спящая G HUB запись не запускает прямые HID++ запросы. Недостающие прямые показания Logitech повторяются только для соответствующих интерфейсов с паузами 3/7/15/30 секунд. Обычные полные проходы сохраняют стартовые интервалы 3/8/16/30 секунд, далее 60 секунд. Дополнительные локальные/Logitech повторы не запускают драйверы Razer/Wolverine и остальных производителей.

[ФАКТ] На событии удаления проверяется наличие точного USB-узла через Configuration Manager. Подтверждённая потеря удаляет запись сразу. Полный успешный снимок HID также удаляет отсутствующие приёмники. Счётчик поколений hotplug/resume блокирует уже находившийся в работе или в очереди `WM_RESULTS` старый снимок. Новые запросы изменения аппаратных настроек не добавлены.

**Рабочий поток, запуск и Explorer**

[ФАКТ] Проверены `main.cpp`, `widget.cpp`, `lifecycle.cpp`, общий HID-слой, расписание опросов, Logitech/G HUB, Razer/Wolverine и механизм HeadsetControl. По исходникам отсутствие устройств не вызывает выход из приложения: сохраняется общий значок/виджет без батарей. Исчезнувший виджет и завершившийся процесс — разные состояния.

Наличие HKCU Run сообщено пользователем и отдельно не проверялось.

[ВЫВОД] Один `START` без последующего `EXIT` не доказывает сбой: процесс мог продолжать работать, быть принудительно завершён или не успеть записать выход. Если запуска вообще не было, старый журнал этого не различает. Автозапуск нельзя считать проверенным только по существованию Run-записи.

[ФАКТ] Внесены минимальные улучшения наблюдаемости и восстановления:

- Проверяются ошибки создания mutex, класса окна, событий, UI-таймера и рабочего потока; ошибки записываются с кодом и возвращают ненулевой код завершения. Ошибка `GetMessage` также различается.
- В журнале различаются запрос выхода через меню, `WM_CLOSE`, завершение сеанса, начало остановки и фактический нормальный выход после остановки потока. Повторный экземпляр пишет `EXIT(already_running)`.
- Добавлен обработчик необработанных Windows-исключений с записью кода и сохранением стандартного механизма Windows error reporting. Запись при тяжёлом повреждении процесса не гарантируется.
- Интерфейс записывает отметку работы раз в пять минут, создание виджета/пересоздание панели Explorer и отсутствие завершённого прохода рабочего потока более двух минут. Это локальная диагностика внутри приложения, без внешнего наблюдателя или перезапуска.
- Результат рабочего потока передаётся через `unique_ptr`; при ошибке отправки память освобождается. При остановке новые результаты не применяются. Поток проверяет остановку между драйверами и при обходе Logitech. События и глобальные структуры живут до завершения производителя сообщений; очередь результатов очищается после присоединения потока.
- Устранено продолжение выхода после непроверенного пятисекундного ожидания. Если драйвер задерживает завершение, это отдельно журналируется, затем ожидается фактический выход потока. Принудительное завершение не добавлено. Уже поставленные в очередь UI-таймеры не пересоздают значки после начала остановки.
- `Shell_NotifyIconW` больше не считается успешным без проверки. Неудачные добавления повторяются; неудачная модификация допускает восстановление через добавление. После `TaskbarCreated` восстанавливается выбранный режим.
- При пересоздании окна виджета сбрасывается кэш подсказки и заново применяются данные. Неизменившееся содержимое виджета не перерисовывается на каждом быстром опросе G HUB.
- Bluetooth-показание больше не подавляется лишь потому, что другое устройство имеет такое же название: требуется совпадение аппаратного контейнера.

[ФАКТ] Механизм HKCU Run, установщик и параметры автозапуска не менялись. Watchdog, служба, задание планировщика, автопереустановка или скрытое восстановление процесса не добавлялись.

**Ограничения и оставшийся технический долг**

[РИСК] Реальные сон/пробуждение G903, G915, одновременная работа G HUB и устройство трея Windows 11 не проверялись. Статические данные и тесты подтверждают алгоритм, но не заменяют аппаратную/визуальную проверку.

[РИСК] «Живое» для G HUB означает новый успешно сопоставленный ответ `ACTIVE`/`CONNECTED` плюс GET батареи. Используемый код не получает от G HUB аппаратную метку времени самой батареи. Если G HUB ошибочно продолжает сообщать ACTIVE со старым значением, обнаружить это по одному неизменному проценту нельзя: неизменный процент сам по себе нормален. Реестровые трёхдневные показания этот путь больше не использует.

[РИСК] Яркость восстанавливается немедленно при применении нового допустимого результата. Обнаружение пробуждения остаётся опросным: обычно следующая локальная проверка после двухсекундной паузы плюс время ответа; при недоступном G HUB действуют HID++ повторы 3–30 секунд. Задержка полного прохода других драйверов также может задержать локальную проверку. Мгновенная аппаратная подписка на пробуждение не реализована. При этом такая задержка не продлевает TTL.

[РИСК] Граница возраста алгоритма строго 90000 мс; Windows UI не является системой реального времени. Физическое исчезновение пикселей происходит на ближайшем обслуживании очереди сообщений/таймера. Это не дополнительный разрешённый период хранения; просроченные данные запрещены в обоих путях рисования.

[РИСК] Неизвестный формат пути G HUB намеренно не сопоставляется по одному PID. Тогда остаётся прямой HID++ путь. Для многопарных приёмников с неоднозначными HID++ слотами и без общего проверенного физического идентификатора межпротокольное объединение ограничено; модельное угадывание не добавлено. Фактический формат путей конкретных G903/G915 ещё требует живой проверки.

[РИСК] Ключи анонимных HID++ устройств теперь включают экземпляр приёмника. Старый выбор скрытия, сохранённый только под PID-ключом, может потребовать повторного выбора в меню; реестр скрытых устройств автоматически не переписывается.

[РИСК] Синхронные `HidD_GetFeature`/`HidD_SetFeature` по всему проекту не получили универсальную отмену/жёсткий тайм-аут. Зависший сторонний драйвер может задержать опрос и остановку; интерфейс самостоятельно удалит устаревшие Logitech-значения и запишет задержку рабочего потока. После пяти секунд при выходе приложение ждёт окончание операции, сохраняя безопасность памяти. Переписывание всех протоколов не выполнялось.

[РИСК] У необязательного HeadsetControl остаются отдельный отсоединённый поток, чтение `g_updated` вне общего замка и работа с собственным дочерним процессом. Основной worker теперь корректно присоединяется, но этот более широкий независимый механизм не переработан. В других драйверах также остаются PID/модельные эвристики и отдельные политики кэша, например Wolverine Xbox. Их правила не заменялись правилами Logitech.

[РИСК] Причина прошлых аудиообрывов не установлена. По коду прямые HID++ чтения отправляют запросы и читают очереди устройств; это не полностью пассивное наблюдение, поэтому совместимость с другим ПО требует отдельной проверки. Исправление исключает дополнительные Razer-проходы при потере Logitech и избегает прямого HID++ при распознанном G HUB сне. Доказательств причинной связи с Voicemeeter/BT-аудио нет. Настройки аудио и оборудования не менялись.

[СЛЕДУЮЩИЙ ШАГ] Отдельная контролируемая проверка staging-сборки на G903+G915: живой процент → сон/NOT_CONNECTED → приглушение до остатка 90 секунд → удаление; пробуждение до срока → один яркий значок с актуальным процентом; извлечение приёмника → удаление без ожидания; перезапуск при спящей мыши → отсутствие старого значка. Затем проверить оба режима отображения и восстановление при обычном пересоздании панели Explorer. Эти действия в текущей работе не выполнялись, чтобы не менять используемое приложение и состояние оборудования.
